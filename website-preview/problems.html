PROBLEM NAVIGATOR

问题导航

不是把问题堆在一起，而是用三层结构理解整个系统：先推演它为什么成立，再进入具体模块，最后理解模块之间如何关联、如何排序与调度。

01
SYSTEM REASONING

总体推演

这一层不解决某个单点问题，而是回答：为什么需要一套系统、为什么由这些部分组成，以及怎样从标准系统长成每个人自己的版本。

01

这套系统的总体目标是什么？

＋
成人端有两个长期目标：财富与幸福；向下一代延伸为家族传承。
系统不是为了让人“懂得更多”，而是让一个人拥有更稳定的身心、更可靠的学习与判断能力、更强的现实创造能力，并把成果沉淀、复利和传递。
02

这套系统到底在解决什么问题？

＋
解决“一个人如何长期发展并持续更新”的系统性问题。
现实问题很少只属于一个模块：效率下降可能同时牵涉睡眠、情绪、目标、信息质量、判断、协作与反馈。单点工具能修局部，但无法解释跨模块问题如何发生。
03

这套系统由哪些模块组成？

＋
五层进化结构 + 九类人际影响 + 能力形成引擎。
五层分别是身心地基、操作系统、领域知识、价值创造、目标与传承；人际影响负责让认知与价值跨主体发生作用；能力形成引擎负责把“知道”推进到“资产化”。
04

为什么这样组成？

＋
因为不同模块承担不同功能，而且存在依赖关系。
身心提供算力；三观、学习与认知负责方向、获取和加工；领域知识提供真实世界的专业材料；价值创造把能力转成结果；目标系统决定“为什么做”；人际影响负责跨主体协同和价值传递。
05

这套系统在现实中如何运行？

＋
不是按目录顺序使用，而是围绕真实问题跨模块调用。
一个“产品卖不出去”的问题，可能要同时检查产品价值、领域判断、用户理解、人际影响、执行节奏甚至个人状态。系统的价值就在于能定位、调用、回退和迭代。
06

如何在标准化基础上形成自己的个性化版本？

＋
标准系统提供公共骨架，个人系统记录自己的高频问题、优势、薄弱项、目标、方法和资产。
最终每个人都应该形成自己的模块权重、调用顺序、工具组合、项目资产与AI协同方式，而不是永远照抄一套标准答案。
07

系统未来如何扩展、传递和升维？

＋
从个人系统向家庭、组织与长期资产扩展。
新的领域知识可以持续挂载；项目经验可以沉淀为方法和工具；成人能力可经过降维进入儿童发展；个人方法也可以产品化、组织化和AI化。
02
MODULE NAVIGATION

模块导航

模块是稳定骨架；问题模式负责诊断；用户语言只是入口。先找到问题属于哪里，再继续向下定位。

M01

身心管理

模块 → 子模块 → 问题模式 → 用户问题。

01 精力与恢复

睡眠、运动、饮食与整体恢复能力。
为什么明明睡够了还是很累？
一忙起来，运动、饮食和作息为什么会一起崩？
高强度用脑之后，怎样判断自己需要休息还是切换任务？

02 情绪与压力

识别、接纳、调节与恢复。
为什么一件小事会在脑子里反复回放？
高压状态结束后，为什么身体和大脑还是停不下来？

03 专注与心流

持续注意、深度工作和高质量状态。
为什么我越来越难持续专注？
什么情况下更容易进入心流？
M02

三观构建

01 世界观与处境理解

结构、历史、人性、制度与个人处境。
为什么同一件事，不同人会得出完全不同的结论？
我的困境是个人问题，还是结构性问题？

02 价值观与人生选择

什么值得追求，什么愿意交换，什么不能让渡。
当财富、自由、家庭、成就冲突时，我到底怎么选？
M03

学习能力

01 学什么

学习目标、边界与路径设计。
进入陌生领域，第一步应该学什么？
怎么判断一个知识点值得深入到什么程度？

02 怎么学

理解、检验、联结、练习和迁移。
为什么看懂了，但一到实际问题就不会用？
怎么确认自己是真的懂了，而不是熟悉了？

03 知识资产

沉淀、检索、更新与复用。

M04

认知体系

L1 信息安检

进入判断系统的信息是否可靠、充分、可用。
AI说得很像真的，我怎么判断能不能信？
信息太多时，哪些值得继续追？

L2 视野校准

系统、演化、尺度、不确定性、边界与模型。
为什么局部看起来正确，整体结果却越来越差？

L3 拆解引擎

定义、拆解、生成、选择。
问题一团乱麻时，到底从哪里开始拆？

L4 表达协同

接收者建模与校准 → 结构与情境 → 依据与判断 → 行动与互动。
为什么我明明说得很清楚，对方理解成了另一件事？
对方自己都说不清关心什么时，怎么沟通？

L5 进化复盘

让一次经验进入下一次调用。
为什么复盘了很多次，下一次还是从头开始？

L6 调度系统

暂停、定位、选择、监控、停止/切换/回退。
什么时候应该继续研究，什么时候应该停下来行动？

M07

人际影响

主树按问题模式管理；营销、教育、管理、协作、谈判、关系、专业服务、公共传播、人机协同作为后续筛选标签。

01 接收者建模与校准

已知、未知、假设与共同基础。

03 依据与判断支持

03
SYSTEM OPERATION

系统运行与调度

模块不是平铺清单。真正使用时，需要理解谁为谁提供输入、问题如何跨模块流动，以及在不同目标与状态下什么应该优先。

01｜模块之间是什么关系？

可以把它理解为“状态 → 操作系统 → 领域材料 → 价值实现 → 目标反馈”的主链，人际影响则横穿其中，负责跨主体传递、协同与价值捕获。

身心管理→三观 / 学习 / 认知→领域知识→价值创造→财富 / 幸福 / 传承
人际影响：贯穿反馈：反向回流AI：各层杠杆

02｜一个真实问题如何跨模块流动？

例如“产品卖不出去”并不自动等于营销问题。可以依次检查：问题是否真实 → 产品是否有价值 → 判断是否可靠 → 用户是否理解 → 行动门槛是否过高 → 自己是否持续执行。真正瓶颈在哪一层，就回补哪一层。

价值问题？→领域判断？→认知质量？→人际影响？→状态 / 执行？

03｜哪个模块应该优先？

没有固定优先级。优先级由当前目标、当前状态、瓶颈位置和依赖关系共同决定。系统构建时强调基础依赖；现实使用时强调“当前最限制结果的那一环”。

目标函数当前状态关键瓶颈依赖关系机会窗口

04｜三条进入路径如何决定优先级？

A｜自下而上适合从零搭系统。优先保证身心地基，再建设操作系统、领域能力和价值闭环。
B｜目标倒推适合目标明确的人。从财富、幸福或家族传承向下反推最需要补的模块。
C｜问题驱动适合已经在实践的人。从当前最痛的问题定位瓶颈，直接回补对应模块。

05｜什么时候应该回退、切换或升级？

当继续投入不能显著增加确定性或结果时，应重新定位：信息不足就回L1；世界理解有问题回L2；问题定义不清回L3；协同走样进L4；经验无法复用进L5；不知道继续还是停止由L6调度。系统允许回退，不要求一直向上。

06｜如何逐渐形成自己的个人系统？

记录自己的高频问题、优势模块、薄弱模块、当前目标、常用工具、典型决策流程、项目资产与AI协同方式。随着反馈积累，标准地图逐渐变成“我的版本”。
